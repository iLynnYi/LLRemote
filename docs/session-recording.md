# 会话录制与后台保存

录制使用一个持续运行的 MediaRecorder，不在切段时重启编码器。约每秒产生的数据按不超过 256 KiB 的块写入磁盘，前端待写队列超过 32 MiB 时停止采集。

内部切段条件为 30 分钟或约 1 GiB，先到者触发。实际切点等待下一个以视频关键帧开头的完整 WebM Cluster，因此阈值是切段目标，不是精确时长或硬性字节上限。解析 EBML 元素边界，不扫描视频负载中的字节模式。各段重新建立时长、时间戳和播放索引；媒体块不重新编码。

## 用户可见行为

- 正常停止：后台保存、合并及验证，最终保留一个 `.webm` 文件。
- 停止采集后释放录制入口；远程操作、会话关闭及新录制不等待合并。
- 空间不足以合并：Toast 提醒一次，计时按钮变黄并显示警告符号，悬浮说明可用空间及预计需求。点击仍然停止录制。
- 空间恢复后按钮恢复红色。恢复阈值参考实际写入增长，避免临界值附近频繁切换。
- 接近无法完成写入和当前段收尾时提前停止，后台尽力保存。
- 合并空间不足时保留可独立播放的分段；其他失败保留已验证分段和未完成原始文件。任务列于右侧“截图与录制”的“后台录制任务”，不依赖原会话仍存在或处于连接状态。
- 可重试保存/合并或另选保存目录。存在尚未写出的内存队列时，先搬迁磁盘任务再按原偏移重试写入；搬迁逐文件校验后才移除原位置的中间文件。

## 空间计算

每 3 秒读取目标卷的实际可用空间。Unix 以设备号识别卷，Windows 以卷 GUID 识别卷，同卷不同目录共享一份需求账本。

`收尾需求 = 各任务待写入数据及其输出需求 + 未完成分段预计输出大小 + 基于实际吞吐量预测的下一采样周期增长 + 后台输出尚未写出的预留量`

`合并需求 = 收尾需求 + 同卷各待合并任务预计最终输出大小`

没有固定 1 GiB 安全余量。分段输出估算计入容器头、Cluster 改写和播放索引；新数据尚未形成完整元素时采用其索引开销上界。后台实际写入会减少尚未写出的预留量，避免重复计算。新后台合并启动时在同一账本锁内检查并登记空间需求。

同卷单段保存使用不覆盖已有文件的原子重命名，不额外复制整份视频。跨卷另存先搬迁并校验任务。多段合并前重新检查空间，不满足条件就保留分段。外部进程仍可能在两次检测间消耗空间，I/O 错误路径因此始终保留可重试数据。

## 完整性与恢复

中间文件位于保存目录的 `.llremote-recording-<UUID>/` 专属目录。清单原子更新，并在应用数据目录登记历史保存位置。启动时扫描这些位置，发现未完成任务后提示用户手动恢复。

每段及合并结果均检查容器结构、时长、SeekHead 和每条关键帧索引，并对所有编码媒体块做 SHA-256 覆盖校验。已完成分段也保存媒体摘要，防止后续合并接受已经损坏的分段。最终文件同步并验证后提交清单，再自动清理中间目录；中途失败不删除恢复材料，也不覆盖已有文件。

异常退出时只尝试恢复完整 EBML 元素，丢弃无法组成完整媒体块的尾部。已经进入磁盘的完整数据可以恢复，尚在编码器或前端队列中的数据不保证恢复。正常停止使用本次录制的采集时长；异常恢复从可用媒体时间戳推算时长。

所有大文件读写、搬迁、合并、验证和恢复在原生后台线程执行，注册表锁仅用于查找任务。后台输出按块让出执行时间；有采集任务时进一步限制连续写入。后台任务独立于 Session 生命周期。

## 验证范围

自动测试覆盖连续流切段与合并、逐块边界解析、空间预警与停止阈值、同卷多任务需求、后台保存不阻塞新录制、断开会话后重试、另存时继续写队列、尾帧截断恢复、媒体及索引损坏拒绝和验证后自动清理。

可用含多个关键帧 Cluster 的 WebM 录像验证真实编码输入。将 `LLREMOTE_RECORDING_SAMPLE` 设置为样本文件，`LLREMOTE_RECORDING_QA_DIRECTORY` 设置为可写的空测试目录，`LLREMOTE_RECORDING_DURATION_MS` 设置为样本的采集时长（毫秒）。从仓库根目录运行以下测试。

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib split_supplied_capture -- --ignored
```

测试会缩短切段阈值，并在测试目录中保存分段副本和合并结果。长时间原生 WebView 录制、真实磁盘写满和跨平台行为需分别验收。
