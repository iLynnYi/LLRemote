# Windows 安装流程

本文描述 Windows 安装器的执行顺序、失败恢复和验证方法。

## 顺序与不变量

1. 安装器初始化：检查真实 Windows 版本（基线 Windows 10 1809）和原生系统架构。按当前产品策略，x86、x64、ARM64 包只能安装到架构完全相同的 Windows；即使系统支持模拟运行也阻止跨架构安装。读取 `IsWow64Process2` 的原生 machine，不能使用 x86 NSIS 引导程序或环境变量代表系统架构。提示只说明此电脑需要的版本、当前包版本和应下载的安装包。无法可靠检测时中止。
2. 解压新主程序到 NSIS 私有临时目录，读取真实 PE machine，并执行无副作用 `--installer-check`。不创建 Tauri/WebView、打开存储、连接后台或停止共享。检查失败发生在 UAC、WebView2 安装及旧应用退出之前。
3. 选择/恢复原安装范围和目录，按需提权；获取全机安装互斥。查询已有服务和当前用户后台，检查目标目录、目录联接、可写性与目标盘/临时盘空间。安装互斥随直接维护子进程继承，父安装器超时退出时仍阻止下一安装器覆盖。
4. 准备 WebView2。Tauri 的 `bundle.windows.webviewInstallMode` 设为 `skip`。项目构建脚本准备对应架构的微软离线安装器，验证 Authenticode 签名后交给自定义 NSIS 模板嵌入。安装器在缺少运行时时执行内置程序，首次安装与更新均可离线完成这一步。整机安装要求机器范围内可用的运行时。安装器再执行实际主程序的 `--installer-verify`，确认 WebView2 Loader 能找到运行时。首次安装与升级须分别在缺少 WebView2 的断网 Windows 上验证。
5. 在中断旧应用或共享之前完整解压资源、外部程序与卸载程序。每个文件单独创建父目录，失败即通过统一错误提示退出，不显示“中止/重试/忽略”对话框，也不允许跳过必需文件。有正在运行的应用或共享才提示一次中断。确认后处理 GUI 进程，用户安装只处理当前用户；停止已有服务与用户后台，但不在此时更新服务二进制。不自动重新开始共享。
6. 对每个包所属文件创建快照，替换应用和卸载程序。只涉及主程序、包内资源/外部程序和卸载程序，不复制或删除整个用户数据目录。
7. 从安装目录执行真实程序加载与 WebView2 验证，再刷新登录启动路径、更新已有服务；整机首次安装在此注册服务。当前用户首次安装不自动创建服务。
8. 必需维护成功后写入正式安装元数据与快捷方式。清除恢复记录/快照，才显示成功完成页；完成页的启动仍使用普通用户令牌。

## 失败与恢复

- 预检失败：退出，不关闭旧应用，不停止共享。目标目录写入探针只在用户选择目录和范围后执行，立即删除探针。
- 替换或安装后加载失败、尚未涉及服务更新：恢复已快照的包所属文件。不会重新开启共享。恢复失败则保留快照并提示部分完成。
- 登录任务、服务更新或元数据发布失败：不在可能更新过的服务下面自动换回旧应用。保留 `.llremote-rollback`、`.llremote-install-recovery.ini` 和 `InstallState=repair_required`，记录目录/版本供相同或更新版本沿原范围修复。重新修复期间遇到失败，也不擅自恢复最初快照。
- 整体安装互斥避免并发安装；直接子进程继承互斥句柄；服务安装/停止的独立 UAC 辅助进程重新打开仅有 SYNCHRONIZE 权限的生命周期句柄。即使外层进程已超时退出，内部辅助进程未退出前仍不能重复安装。超时仍须结合日志、实际进程和服务状态处理。
- 每次安装使用独立的临时日志；失败提示只呈现用户能采取的下一步，以及必要的恢复/修复状态。阶段、系统内部版本、包架构、原生错误和诊断路径不出现在普通用户弹窗中，技术信息保存在日志中。CreateProcess 原生错误与进程退出/加载器状态分别记录，退出状态同时记录十六进制。运行时使用协议版本 1 的结果文件握手，不依赖 GUI 子系统的 stderr。

## 维护结果

| 状态 | 含义 |
| --- | --- |
| 0 | 无副作用加载/验证/维护成功；状态查询时表示没有已有运行时 |
| 10–13 | 仅在状态查询中表示已有服务、运行中的服务或用户后台；准备更新仍以 10 表示已有服务 |
| 80 | 安装维护参数不合法 |
| 81–84 | 服务查询、服务停止、用户后台查询/停止、登录注册阶段失败 |
| 85–88 | UAC 取消、策略拒绝、服务访问拒绝、服务 IPC 超时 |
| 89 | 报告缺失、协议不符或报告无法写入 |
| 90–93 | 服务维护失败、二进制复制失败、SCM 注册失败、操作账户授权失败 |
| 94 | WebView2 Runtime 不可用；报告保留 HRESULT |
| 95 | 无法记录或验证安装所属账户；安装保留为需要修复，不继续维护服务 |

报告只写入有界的机器错误码；不输出配置内容、密码或凭据。其他退出状态可能来自加载器或进程异常，不能转换为“权限不足”。

## 跨用户卸载

- 安装在写入共享服务前保存 `.llremote-install-owner`，记录范围与个人安装所属账户的 SID。个人卸载绑定该 SID，其他用户必须提权代卸载；整机卸载将原操作账户 SID 带过 UAC。元数据须与相应用户或机器的卸载注册记录匹配，不把未知安装当成管理员自己的个人安装。
- 个人路径从目标账户的 ProfileList 和用户配置单元解析。读取卸载信息不获取或复制其他账户的进程令牌。跨账户且目标已登录时，通过无触发器的临时 Task Scheduler 任务，在目标现有会话中以 LeastPrivilege 运行个人清理辅助进程；辅助进程再次校验实际 SID，预检成功后才允许机器级清理，结束后删除任务。不能把管理员等同于其他账户令牌的复制权限，也不使用 S4U 或存储账户密码。
- 未登录账户的普通卸载用唯一临时键挂载其配置单元，并在操作后关闭、卸载及恢复 Backup/Restore 权限；不用要求整棵树统一 ACL 的 RegLoadAppKey 加载 NTUSER.DAT。清理保存密码需要真实登录会话；无法取得时保留密码并报告残留，仍可移除应用和可访问的数据。目标会话不可用时仅在确认没有仍运行的用户共享后台、并能解除有效共享自启动后继续。
- 删除个人数据前，按所属账户和完整可执行文件路径关闭仍运行的主程序。管理员在 WTS 枚举之前临时启用已有的 SeDebugPrivilege，防止其他账户进程的 pUserSid 因权限不足为空；快照取得后恢复原状态。关闭进程遇到拒绝时再按需临时启用并恢复，不修改进程 ACL。跨账户无法确认主程序所属账户时明确中止，不把空 SID 当成其他安装。无法查询或停止匹配的主程序时必须中止，不能跳过后继续删除被占用的数据库。
- 个人安装关联了系统共享服务时，卸载预检即申请管理员授权，并携带原目标 SID 重启卸载器；关闭主程序、移除服务和个人清理均在授权后开始。没有管理员凭据、取消或被策略拒绝时，保留程序、个人数据与卸载入口，明确提示联系管理员，不提供跳过服务的完整卸载。准备阶段再次核对服务授权，服务清理不再事后弹出 UAC。`/UPDATE` 保留服务，不因关联服务额外申请卸载授权。
- 服务在受保护的 Server 安装目录记录创建它的应用目录，其他用户更新服务时保留归属。应用卸载只移除关联服务；已有服务无归属信息时要求显式更新/修复或单独卸载，不猜测。
- 从安装包选择卸载时，安装包在临时目录生成卸载器，并传入原安装记录中的目录。卸载器自带维护程序，启动时会核对目标归属。旧程序、旧卸载器或包内资源已缺失时继续清理，并在卸载日志中记录。
- 核心阶段依次确认授权、关闭主程序、停止用户共享后台并解除有效自启动、停止并删除关联服务；这些步骤失败仍中止。系统服务密码清理失败不会阻止 Stop/DeleteService，删除服务失败则不能降级为警告。
- 可选清理按每个文件或目录收集残留：个人数据、缓存、个人/服务凭据、失效快捷方式和注册记录失败后继续其他清理和主程序删除。截图、录像及接收文件保留。文件共享/锁冲突重试共用五秒预算，不重试权限或危险路径错误。
- 卸载器保留恢复入口直到核心文件移除。主程序可被可靠安排重启删除时标记“需要重启完成卸载”，不能安排才失败。主程序移除后的注册表/快捷方式/辅助文件残留只产生警告；不因为这些残留把已移除的主程序显示为卸载失败。
- CleanupReport 通过有界 JSON 从所属账户任务传回，再由主辅助进程写入带 BOM 的 UTF-16 INI 给 NSIS。报告新建时拒绝覆盖和重解析路径，路径只用于显示，不作为特权删除输入。完成码 0/200/201/202 分别表示完成、完成有残留、需要重启、需要重启且有残留；NSIS 汇总前后阶段清单，结束后显示原因/位置/建议，完整 Unicode 清单保留在操作账户临时目录。正常卸载整体返回 0，可靠安排重启删除返回 3010；UAC 完成收据区分普通完成和需重启，上层维护入口接受 3010。
- 卸载错误从个人清理任务、主辅助进程到 NSIS 均保留分类；已知失败显示具体阶段、对应处理建议、安装目录和错误码，不再统一提示“无法停止共享或清理数据”。未知辅助进程退出或崩溃保留原退出码，并明确标为未识别错误，不猜测权限原因。
- 退出码 101/102 为归属未知/目标记录不匹配，103 为目标未登录，104 为目标会话执行失败，105 为服务归属未知，106 为配置单元不可用，107 为主程序关闭失败，108 为服务未授权；109–113 分别为用户共享后台、快捷方式、自启动、注册表、个人凭据清理失败；114–117 分别为数据清理失败、文件占用、目录拒绝访问、数据路径重定向；118–123 分别为服务移除、服务访问拒绝、服务超时、程序缺失、辅助程序复制、辅助程序启动失败；124–128 分别为进程归属未知、进程访问拒绝、路径查询失败、进程退出超时、目标账户清理超时；129–134 分别为安装配置无效、未获管理员权限、服务停止失败、服务凭据清理失败、预检报告写入失败、程序文件删除失败。

## 构建与验证边界

Windows 构建显式指定 MSVC 目标；候选验证使用 7-Zip 解包，检查每份主程序副本及资源与构建输入的摘要一致，再从解包目录运行加载握手。安装器本身始终为 x86，不能用它的 PE machine 代表应用架构。

CI 包含 Windows x86、x64 和 ARM64 构建。打包后运行真实 NSIS 函数和宏的回归夹具，覆盖三个架构的全部九种组合与未知架构、嵌套资源解压、目录和文件写入失败、加载握手、失败后的状态记录、文件回撤及服务更新顺序。夹具用模拟操作替代 SCM 和 IPC，验证范围限于安装器逻辑。

## 安装目录与后续升级

默认目录为当前用户的 `%LOCALAPPDATA%\LLRemote\App` 或整机的 `%ProgramFiles%\LLRemote\App`。升级和修复沿用注册记录中的目录、安装范围和所属账户。安装中断后，在原目录运行相同或更新版本进行修复。

系统服务记录创建它的应用目录，其他账户更新共享服务时保留该归属。业务数据和 WebView 偏好的路径见 [Windows 存储目录设计](../design/windows-storage-layout.md)。
